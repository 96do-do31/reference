# 33m2 — 게스트(임차인) 유저 플로우

## FLOW-G01 매물 탐색 → 계약 요청 (핵심 전환 경로)

```
/guest/main
  └─ 검색바(지역·지하철·대학교 / 일정) 또는 매물유형 숏컷 또는 "지도로 찾아보기"
      ↓
/guest/search?lat&lng&zoomLevel
  ├─ 좌측: 매물 카드 리스트 (무한스크롤/페이지네이션)
  ├─ 우측: 네이버 지도 + 마커
  ├─ 상단 필터: 일정 / 방 개수 / 가격 / 건물유형 / [초기화]
  └─ 지도 이동 시 bbox 기반 재조회 (마커·리스트 각각 별도 API)
      ↓ 카드 클릭 (⚠️ 새 탭으로 열림)
/guest/room/{rid}
  ├─ 갤러리 · 구조 · 옵션 · 위치/교통 · 계약정보 · 후기 · 임대인 소개 · 환불규정
  └─ 우측 스티키 카드: 가격 요약 → [계약 시작하기]
      ↓
[모달] 2단계 날짜 선택
  ├─ 1단계: 입주 날짜 (월 단위 캘린더, 예약불가일 취소선)
  └─ 2단계: 이용 기간 (1~12주 그리드, 각 항목에 퇴실일 표시)
      · minimumContractWeeks 미만 주수는 비활성
      · 선택 기간 내 예약불가일이 끼면 해당 주수 비활성
      ↓ 기간 선택 시 우측 카드에 견적 즉시 반영
[계약 시작하기]
      ↓
/guest/contract/request?rid&startDate&endDate&entryPoint
  ├─ 방 정보 (도로명/지번 + 각각 복사 버튼)
  ├─ 임대기간 (입주일/퇴실일)
  ├─ 결제금액 상세
  ├─ 계약 취소 시 환불 규정 (⚠️ 실제 달력 날짜로 전개)
  ├─ 계약 절차 안내
  └─ 임대인에게 인사 메시지 (0/500자)
      ↓ [계약 요청하기]   ← 여기서부터 임대인에게 실제 요청 발송
```

> `entryPoint=room_detail_start_lease` — 진입 경로를 쿼리로 추적 (전환 분석용).

## FLOW-G02 계약 라이프사이클 (상태 머신) ★

서비스가 명시한 절차:

```
계약 요청 → 임대인 계약 승인 → 결제 → 입주 → 퇴실 → 임대인 퇴실 확인 → 보증금 반환
```

| 단계 | 주체 | 규칙 |
|---|---|---|
| 계약 요청 | 임차인 | 인사 메시지 동반. 채팅 스레드 개설 추정 |
| 승인/거절 | 임대인 | **24시간 이내** 응답 (타임아웃 시 자동 만료 추정) |
| 결제 | 임차인 | **승인 후 결제 시점에 계약 확정** |
| 입주 | — | `startDate` 도래 |
| 퇴실 | — | `endDate` 도래 |
| 퇴실 확인 | 임대인 | 파손·정산 확인 게이트 |
| 보증금 반환 | 플랫폼 | 에스크로 해제 |

> 💡 **Airbnb와의 결정적 차이**: Airbnb는 예약 시점에 결제(즉시예약) 또는 예약요청+사전승인 결제. 33m2는 **승인이 선행되고 결제가 후행**하며, 퇴실 확인·보증금 반환이라는 임대차 고유 단계가 존재.

### 미확인 상태 (추가 조사 필요)
- 거절(rejected), 요청 만료(expired), 결제 대기 만료
- 취소(cancelled) — 취소 주체별 분기(임차인 귀책 / 임대인 귀책)
- 연장(extension) — "13주 이상 원할 경우 계약 체결 후 거주 기간 연장 신청"

## FLOW-G03 요금 계산 (검증된 산식)

샘플: `rid=100260`, 2주, 임대료 120,000원/주, 관리비 30,000원/주, 청소비 30,000원, 보증금 330,000원

```
임대료      = weeklyRent × weeks              = 120,000 × 2 = 240,000
관리비      = weeklyMgmtFee × weeks           =  30,000 × 2 =  60,000
청소비      = cleanFee (1회성)                            =  30,000
                                                ─────────────────────
소계(할인 전)                                              = 330,000
계약 수수료  = 소계 × 9.9%                                 =  32,670  ✓ 정확히 일치
                                                ─────────────────────
실 이용 금액                                               = 362,670
보증금      (별도, 반환 대상)                              = 330,000
                                                ─────────────────────
최종 결제 금액                                             = 692,670
```

**계약 수수료율 = 9.9%** (임대료+관리비+청소비 기준). → 플랫폼 게스트측 수수료.
할인이 있는 매물의 경우 `discountedUsingFee`가 임대료 자리에 대입되는 것으로 추정 (미검증).

**기간 계산**: 입주일 2026-10-20(화) → 퇴실일 2026-11-02(월). 2주 = 14일이며 **퇴실일은 마지막 숙박일**(입주일 포함 14일째).

## FLOW-G04 환불/위약금 정책

정책은 **임대인이 프리셋을 선택**하며 매물마다 다름 (`refundPolicy` enum + `refundTerms` 테이블).

| 관찰 사례 | 15일 전 | 8일 전 | 1일 전 | 당일 이후 |
|---|---|---|---|---|
| `rid=4684` (`MIDDLE`) | 10% | 30% | 50% | 취소 불가 |
| `rid=100260` (엄격 추정) | 20% | 50% | 70% | 취소 불가 |

**위약금 부과 기준액 = 임대료 + 계약 수수료** (관리비·청소비·보증금 제외)

**공통 규칙 (정책 무관)**
1. **결제 당일 취소** → 환불규정과 무관하게 (임대료+계약수수료)의 **10%만** 부과
2. **무료 취소 기간** 해당 시 전액 환불
3. 취소 시 **관리비·청소비·보증금은 항상 전액 환불**
4. **임대인 귀책 취소 시 동일 기준의 위약금을 임대인이 임차인에게 지급** ← 양방향 대칭 페널티

> 💡 4번은 좋은 설계. Airbnb도 호스트 취소 페널티가 있지만 게스트에게 직접 동일 기준으로 지급하는 구조는 아님.

## FLOW-G05 예약 가능일 판정 로직 (API 의미 확정)

```http
GET /v1/use-auth/rooms/{rid}/schedules?year=2026&month=9
→ {"code":"SCSS_001","data":{"schedules":[{"date":"2026-09-01","status":"booking"}, …]}}
```

- 응답에는 **점유된 날만** 포함됨
- `status: "booking"` = 기존 계약으로 예약된 날
- `status: "disable"` = 임대인이 차단한 날
- **응답에 없는 날 = 예약 가능**

> 검증: `rid=4684` 2026-09 응답의 미포함일 `[7,21,22,23,24,25]` 이 캘린더 UI의 선택 가능일과 정확히 일치.

**기간 선택 활성화 조건**
```
weeks 선택 가능  ⟺  weeks >= minimumContractWeeks
                 AND [startDate, startDate + weeks*7 - 1] 구간에 점유일 없음
                 AND weeks <= 12
```
