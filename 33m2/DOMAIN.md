## 1. 계약 모델 — 2단 구조 ★

```
ContractMaster (계약 마스터)          ← 연장 체인의 루트. cid로 식별
  ├─ initialContractId               최초 계약 ID
  ├─ contractMasterStatus            ACTIVE | CLOSED | CANCELED
  ├─ startDate / endDate             ★ 연장 포함 전체 기간 (합산)
  ├─ deposit                         330,000 고정
  └─ contractList[]                  ← 개별 계약 (연장 시 append)
        ├─ contractId
        ├─ contractStatus            CONTRACT_COMPLETE | CANCEL | …
        ├─ contractStatusDescription 취소 사유 문구
        ├─ week                      계약 주수
        ├─ startDate / endDate       해당 계약 구간
        ├─ hostPayTime               정산 실행 시각
        ├─ totalUsingFee             이용 금액
        └─ hostPayAmount             정산 금액 (= totalUsingFee × 0.967)
```

**검증 사례**: `cid=930906`, `initialContractId=794794`, 전체 기간 2026-06-28 ~ 08-29,
`contractList` 4건 (결제완료 2 + 취소 2), 마스터 상태 `ACTIVE`.

> 💡 **원계약 4주 + 연장 5주 = 9주**가 마스터의 `startDate~endDate`로 합산 표시됨.
> 취소된 시도도 `contractList`에 남아 이력이 됨.

## 2. 상태 enum (전체 확정)

### 2.1 `contractMasterStatus`
| 값 | 의미 |
|---|---|
| `ACTIVE` | 진행 중 |
| `CLOSED` | 종료 |
| `CANCELED` | 취소 |

### 2.2 `contractStatus` (개별 계약)
확인된 값: `CONTRACT_COMPLETE`, `CANCEL`
> ⚠️ 나머지 코드값 미확인. 아래 UI 라벨과 1:1 대응 추정 ❓

### 2.3 UI 표시 상태 — 게스트 (`guest_lease_list.status.*`)
| 키 | 라벨 |
|---|---|
| `lease_pending` | 계약대기 |
| `movein_waiting` | 입주대기 |
| `staying` | 거주중 |
| `moving_out` | 퇴실중 |
| `lease_ended` | 계약종료 |
| `cancelled` | 취소 |
| `payment_cancelled` | 결제취소 |

### 2.4 결제 축 상태 (`guest_lease_list.contract.status.*`)
| 키 | 라벨 |
|---|---|
| `approval_pending` | 승인대기 |
| `payment_pending` | 결제대기 |
| `payment_completed` | 결제완료 |
| `canceled` | 취소 |
| `payment_canceled` | 결제취소 |

> ⭐ **상태가 2축**입니다: 계약 진행 축(계약대기→입주대기→거주중→퇴실중→계약종료)과
> 결제 축(승인대기→결제대기→결제완료). 구현 시 분리 권장.

### 2.5 취소 사유 (`contractStatusDescription` 실측값)
```
"다른 임차인의 결제로 취소되었습니다."
"임차인이 결제하지 않아 취소되었습니다."
"계약이 취소되었습니다."
"임대인이 요청을 승인하지 않아 계약이 취소되었습니다."   ← guest_lease_list.contract.notice
```


## 4. 서버 주도 액션 가용성 플래그 ★

`ContractMaster`가 **버튼 활성화 여부를 직접 내려줍니다**. 클라이언트는 상태 조합을 계산하지 않습니다.

| 플래그 | 대응 액션 |
|---|---|
| `isCallAvailable` | [전화하기] 노출 |
| `isCheckFinishAvailable` | [퇴실 점검 완료] (임대인) |
| `isDepositDeferAvailable` | **보증금 지급 유예** 신청 |
| `isDepositDeferReleaseAvailable` | 보증금 지급 유예 해제 |

동반 필드:
```jsonc
"tooltipMessage": {
  "checkFinishMessage": null,           // 비활성 사유 툴팁
  "depositDeferReleaseMessage": null
},
"scheduleChangeAnswerAlert": null,      // 일정 변경 요청 응답 알림
"samsamCareUrl": null                   // 삼삼케어(부가 서비스) 링크
```

> 💡 **채택 권장 패턴**: 상태 머신이 복잡할수록 클라이언트가 조건을 재구현하면 불일치가 납니다.
> 서버가 `canX` 플래그 + 비활성 사유 메시지를 함께 내려주는 설계가 안전합니다.

> 🆕 **보증금 지급 유예(deposit defer)** — 임대인이 손해배상 사유로 보증금 반환을 보류하는 기능. 기존 문서에 없던 개념.

## 5. 서브플로우

### 5.1 입주 확인 (`movein_confirm`)

임차인이 입주 후 수행. 미완료 시 툴팁 "입주 확인을 완료해 주세요".

```
제목: "{name}님, {roomName}에 안전하게 입주하셨나요?"

확인 질문 2가지
  ├─ 출입 가능한 비밀번호, 열쇠를 받으셨나요?
  └─ 집 내부를 확인하셨나요?

보증금 반환 계좌 입력
  ├─ 은행 선택 · 계좌번호(숫자만) · 예금주명
  └─ [예금주 확인]  ← 실명 검증 API

영수증 발급 신청  (신청 / 신청 안함)
  └─ "삼삼엠투는 서비스 수수료에 대한 세금계산서/현금영수증을 발행해 드립니다."

간이 리뷰: "입주한 집은 어떠신가요?"

안내
  ├─ 가전·가구 고장 등 특이사항은 확인 후 임대인에게 알릴 것
  └─ 흡연으로 인한 냄새·오염은 손해배상 청구 대상

버튼: [입주 완료하기] / [아직이요]
```

> ⚠️ **일정 변경은 입주 확인 완료 시점에 잠깁니다** (아래 5.3 참조).

### 5.2 퇴실 및 보증금 반환 (`moveout`, `early_moveout`)

```
[퇴실하기] → 퇴실 및 보증금 반환 신청

보증금 반환 계좌 (은행/계좌번호/예금주 + 예금주 확인)
  또는
보증금 반환 안내 (카드결제 건)
  └─ "결제 금액에서 보증금이 부분 취소 됩니다."
  └─ "반환 완료 후, 3~7일 이내 카드 취소로 환불됩니다."

후기 작성 (아래 6절)

완료 → "보증금 반환 신청이 완료되었습니다"
       "보증금은 삼삼엠투에서 보관 중이며, 임대인의 퇴실 확인 후 순차적으로 반환됩니다."
```

**중도 퇴실 (early_moveout)**
- 퇴실일 이전에 조기 퇴실 → 보증금을 먼저 수령
- ⚠️ **"남은 기간에 대한 이용금액은 환불 받을 수 없습니다."**
- ⛔ 연장 계약이 있으면 불가 → "마지막 계약을 취소 후 퇴실해 주세요"

### 5.3 일정 변경 요청 (`contract.tenant.schedule_change` / `landlord.respond_reschedule`) 🆕

계약 취소의 **대안**으로 제공되는 별도 승인 플로우.

```
임차인                                    임대인
──────                                    ──────
[일정 변경 요청하기]
  ├─ 변경할 입주 날짜 선택 (달력)
  ├─ 요청 메시지 (★ 5자 이상 필수)
  └─ [요청 보내기]
        │
        ├──────────────────────────────►  알림: "{schedule} 임차인이 일정 변경을 요청하였습니다."
        │                                 [임차인에게 답변하기]
        │                                   ├─ 임차인 메시지 / 현재 일정 / 변경 일정
        │                                   ├─ [달력 보기]로 충돌 확인
        │                                   └─ [일정 변경 승인] / [일정 변경 거절]
        │                                        └─ 거절 사유 입력 (선택)
        ▼
  변경요청 → 변경확정 (승인) 또는 변경취소 (거절/임차인 취소/자동 취소)
```

| 상태 | 라벨 | 설명 |
|---|---|---|
| 요청 | 변경요청 / 변경 승인 대기 | 임대인의 일정 변경 승인을 기다리고 있습니다. |
| 확정 | 변경확정 | 임대인이 일정 변경을 승인하였습니다. |
| 취소 | 변경취소 | 임대인이 승인하지 않음 / 임차인이 취소 / **자동 취소** |

**제약 규칙**
- 🔒 ★ **총 계약 기간은 유지되어야 함** — FAQ 원문: *"총 계약 기간은 그대로 유지한 상태에서 입주일과 퇴실일만 조정할 수 있으며, **계약 기간 자체를 늘리거나 줄이는 변경은 불가**합니다."*
  ⇒ 일정 변경 = **기간 고정 이동(shift)**. 기간 변경은 연장 또는 취소로만 가능.
- 🔒 임대인 답변 가능 시한: **"입주일 당일, 임차인의 입주 확인 전까지"**
- ⛔ 입주일이 지났거나 **입주 확인 완료** → 변경 요청 불가
- ⛔ 해당 일정에 이미 확정된 계약 존재 → 승인 불가 ("요청을 거절하고 임차인에게 안내해 주세요")
- 중복 요청 방지: "이미 일정 변경을 요청한 계약입니다"
- 임차인은 요청 후 [일정 변경 취소하기] 가능
- 이력: [일정 변경 현황 보기]

### 5.4 계약 연장 (`extend_lease`, `guest_lease_list.dialog.extend_contract`)

이미 계약한 방을 다시 계약할 때 모달로 분기:

| 선택지 | 설명 |
|---|---|
| **계약 연장하기** | 기존 계약에 **이어서** 계약 (같은 ContractMaster에 append) |
| **새로 계약하기** | 기존 계약과 **별도로** 계약 (새 ContractMaster) |

**연장 계약 요금 규칙 ★**
- ⭐ **"연장계약은 청소비와 보증금이 청구되지 않습니다."**
- ⭐ "연장 계약시 보증금은 추가 결제되지 않습니다."
- "퇴실 후 재입주하시는 경우에는 새로운 계약으로 요청해 주세요."
- 기간 선택 UI는 신규 계약과 동일 (1주/2주… 그리드)

### 5.5 계약 취소 (`lease_cancel`, `cancel_payment`)

```
[계약 취소]
  ├─ 취소 사유 선택
  │
  ├─ 분기 A: 입주일을 변경하고 싶은 경우
  │    → "계약 취소 없이 임대인에게 일정 변경을 요청할 수 있습니다"
  │    → [일정 변경 요청하러 가기]   (5.3으로 유도)
  │
  ├─ 분기 B: 임대인이 취소를 요청한 경우
  │    → ⚠️ "임차인님이 대신 계약을 취소하시면 위약금이 부과될 수 있습니다"
  │    → [임대인에게 채팅하러 가기]  (임대인이 직접 취소하도록 유도)
  │
  └─ 진행 → 환불 금액 확인 화면
        ├─ 총 결제금액
        ├─ 계약 취소 위약금 (임대료의 N%)
        ├─ 취소 수수료 (계약 수수료의 N%)
        ├─ 최종 환불 금액
        ├─ 환불 계좌 (은행/계좌번호/예금주 + 예금주 확인)
        ├─ 영수증 발급 신청
        └─ [계약 취소하기]
```

**위약금 산식 (i18n 원문)**
> "계약 취소 시 **임대료와 계약 수수료의 {N}%** 의 위약금이 부과됩니다."
> "관리비, 청소비, 보증금은 **전액 환불**됩니다."

⛔ 연장 계약이 있으면 취소 불가 → "마지막 계약을 먼저 취소해 주세요"
✅ 완료 후: "3일 이내에 환불이 완료됩니다."

### 5.6 결제 완료 (`payment_complete`)

```
"계약이 확정되었습니다"

안내: 보증금은 삼삼엠투에서 보관하며, 임대인의 퇴실 확인 후 반환됩니다.

```

## 6. 리뷰 도메인 ★

### 6.1 작성 플로우 (퇴실 시 `moveout.review` / 별도 `write_review`)

```
1. 평점          "사용에 만족하셨나요? 평점을 남겨주세요"  (별점 필수)
2. 간이 리뷰      "어떤 점이 좋으셨나요?" → 태그 선택 (SimpleReviewTemplate)
3. 공개 후기      5자 이상 ~ 1000자 이내 (필수)
4. 비공개 후기    "임대인에게만 전달됩니다 (선택)"          ← 🆕
```

### 6.2 공개 규칙 ★★
> **"작성하신 후기는 보증금 반환 완료 후 공개됩니다."**
> **"후기는 보증금 반환 완료 후 공개되며, 공개된 이후에는 수정이 불가합니다."**
> 수정/삭제는 **고객센터 1:1 문의**로만 가능.

⇒ 리뷰에 `visibleAt` / `isPublished` 개념 필요. 보증금 반환 이벤트가 트리거.
⇒ 보복성 리뷰 방지 장치 (Airbnb의 14일 동시 공개와 목적 동일, 메커니즘은 다름).
