# 33m2 — 임대인(호스트) 화면·데이터 모델

> 실계정 관찰 (매물 1건 운영 중, 계약 이력 다수). 개인정보(주소·성명·계좌)는 구조만 기록하고 값은 생략.

전역 헤더: 로고 / [방관리] [계약] [채팅] / 임차인 모드로 전환 · 알림벨 · 계정

## SCR-H01 대시보드 `/host/main`

3개 위젯 (각각 "17:31 기준" 타임스탬프 + 새로고침 아이콘):

| 위젯 | 항목 |
|---|---|
| **할 일** | 승인대기 · 퇴실점검 |
| **정산 예정 임대료** | 총 N건 / N원 → `/host/pay` |
| **계약 현황** | 계약대기 · 입주대기 · 거주중 · 퇴실중 → `/host/contract` |

하단: 운영 팁 콘텐츠 카드 6종 · FAQ 3선 · 앱 다운로드 배너
> 진입 시 프로모션 모달 ("오늘 하루 보지 않기" / "닫기")

## SCR-H02 방 관리 `/host/room`

- 헤더: "방 관리" + **[+ 방 등록하기]**
- 필터: 전체보기 ▾ / 검색(주소, 방 이름)
- 카드: **상태 배지(공개/비공개)** · 썸네일 · 방 이름 · 주소 · `N원 / 1주` · [수정하기] [일정 관리하기] · 케밥 메뉴
- 케밥 메뉴: **미리보기 / 복사하기 / 방 비공개하기 / 삭제하기**

> 💡 **복사하기(복제)** — 동일 건물 여러 호실을 운영하는 호스트에게 핵심 기능. 실제로 `⑨ 가산역 신축 풀옵션`, `⑩ 가산역 신축 풀옵션` 같은 번호 매긴 매물군이 관찰됨.

## SCR-H03 방 등록/수정 위저드 ★ (호스트 입력 모델 전체)

5단계: **1 공간 → 2 임대료 → 3 옵션 → 4 방 설명 → 5 일정**
URL로 단계 이동 가능 (`?step=N`), `returnTo` 파라미터로 복귀 지점 지정.

### Step 1 — 공간

| 필드 | 타입 | 제약 |
|---|---|---|
| 주소 | 도로명 + 지번 | ⚠️ **수정 불가** — "새로운 주소 등록이 필요하신 경우 방을 다시 등록해 주세요" |
| 층수 | select | `지하, 반지하, 1층 … 85층` (88개 옵션) |
| 상세 주소 | text | ⚠️ **"상세 주소는 계약이 확정된 후 공개됩니다"** — 동/호수 프라이버시 보호 |
| **건물 유형** | 단일 선택 (12) | 아래 |
| 구조 | 스테퍼 ×4 | 방 / 화장실 / 주방 / 거실 — "임차인이 단독으로 사용하는 공간만" |
| 복층 | checkbox | "복층이 있습니다." |
| 전용 면적 | number (평) | "공급 면적이 아닌 전용 면적 기준" |
| 엘리베이터 | 라디오 | 있음 / 없음 |
| 주차 | 라디오 | 가능 / 불가능 → 가능 시: **무료(여유) / 무료(선착순) / 유료** |
| 주차 안내 | text (선택) | 100자 |

**건물 유형 enum (12종, 완전 목록)**
```
오피스텔 · 아파트 · 원룸건물 · 연립빌라 · 단독주택 · 상가주택
게스트하우스 · 호텔 · 모텔여관 · 펜션 · 고시원 · 쉐어하우스
```
> API에서는 코드값으로 내려옴 (예: `원룸건물` → `STUDIO`). 전체 매핑은 추가 확인 필요.

### Step 2 — 임대료 ★

| 필드 | 값/제약 |
|---|---|
| **1주 임대료** | number, 원/1주 |
| **보증금** | ⚠️ **플랫폼 고정 330,000원 — 호스트 설정 불가** |
| 1주 관리비 | number, 원/1주 |
| 관리비 포함 항목 | 가스 / 수도 / 전기 각각 `포함 · 불포함` |
| 관리비 상세 설명 | 300자 + **"자주 쓰는 문구 불러오기"** (저장된 문구 재사용) |
| 퇴실 청소비 | number, **입주 시 1회 청구** |
| 환불 규정 | `약한 / 보통 / 강한` 3택 + 확인 체크박스 (필수) |

> 보증금 고정: "삼삼엠투 계약의 보증금은 33만 원으로 설정됩니다. 보증금은 삼삼엠투에서 보관하며 임대인님께서 **퇴실 상태를 점검한 후** 반환됩니다."
> 관리비: "삼삼엠투는 **관리비 정산을 대행하지 않으므로**, 평소 관리비를 고려하여 설정을 추천"

**장기 계약 할인** (복수 구간 추가 가능)
- 기간: `2~12주 이상 계약 시`
- 할인율 옵션: `5, 6, 7, 8, 9, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55, 60, 65, 70, 75, 80` (%)

**즉시 입주 할인** (복수 구간 추가 가능)
- `오늘부터 N일 이내 입주 시, N만 원 할인`

**환불 규정 프리셋 — 정확한 값 (ENT: RefundPolicy)**

| 취소 시점 | 약한 `WEAK` | 보통 `MIDDLE` | 강한 `STRONG` |
|---|---|---|---|
| 입주일 15일 이전 | **무료 취소** | 10% | 20% |
| 입주일 8일 이전 | 20% | 30% | 50% |
| 입주일 1일 이전 | 40% | 50% | 70% |
| 입주일 당일 이후 | 취소 불가 | 취소 불가 | 취소 불가 |

> ✅ 검증: `rid=4684` → `refundPolicy:"MIDDLE"`, UI 10/30/50 일치. `rid=100260` → UI 20/50/70 = `STRONG`.
> ⚠️ 표기 불일치: 호스트 화면은 "**임대료의** N%", 게스트 화면은 "**임대료와 계약 수수료의** N%". 게스트 기준이 실제 부과 기준으로 보임.

### Step 3 — 옵션

| 그룹 | 항목 |
|---|---|
| **기본 옵션** (고정 7종) | 냉장고 · 세탁기 · 에어컨 · 와이파이 · 싱크대 · 인덕션 · 침대 |
| **추가 옵션** | 도어락 · CCTV · 관리실 · 식탁 · 전자레인지 · 책상 · 옷장 · 신발장 · 화장대 · 비데 · 건조기 · 커튼 · 공기청정기 · (TV · 가스레인지 · 밥솥 · 정수기 · 소파 · 욕조 · 발코니 · 드레스룸 · 케이블TV 등) |
| 반려동물 동반 | 허용 / 허용 안 함 |

> 선택하지 않은 항목이 게스트 상세의 `missingOptions`로 노출됨 (= 명시적 "없음" 표기).

### Step 4 — 방 설명

| 필드 | 제약 |
|---|---|
| 방 이름 | "방의 위치와 특징을 담은 짧은 이름이 효과적" |
| **방 사진** | **최소 6장 ~ 최대 20장**, 대표 사진 지정, 드래그로 순서 변경 |
| 방 소개 | **300자** |
| 방 이용 방법 (선택) | **700자** |
| 교통편 | **200자** |
| 추가 설명 (선택) | **700자** |

### Step 5 — 일정

| 필드 | 값 |
|---|---|
| **최소 계약 기간** | `1주 ~ 12주` select |
| **입주일 운영** | 입주일에 앞 계약 받기 / 받지 않기 |
| **퇴실일 운영** | 퇴실일에 다음 계약 받기 / 받지 않기 |

> 💡 **당일 턴오버 제어**. 퇴실일에 다음 계약을 받으면 공실 0일 운영 가능. Airbnb의 `turnover_days` 개념과 동일하나 입주/퇴실을 각각 제어.

## SCR-H04 일정 관리 `/host/room/{rid}/schedule`

- 다중 월 캘린더 그리드 (2열, 과거 월 포함)
- 범례 3상태: **계약가능(기본) / 계약불가능(빨강 취소선) / 계약완료(파랑)**
- 우측 패널: 날짜 선택 → 라디오 `계약 가능으로 설정 / 계약 불가능으로 설정` → [적용하기]

**API 상태 매핑 확정**
| UI | `schedules[].status` | 의미 |
|---|---|---|
| 계약가능 | (응답에 없음) | 예약 가능 |
| 계약불가능 | `disable` | 임대인이 차단 |
| 계약완료 | `booking` | 계약 체결됨 |

> ⚠️ **날짜별 가격 설정 없음** — 성수기/주말 요금 등 다이나믹 프라이싱 미지원. 가격은 단일 주간 요율 + 할인 테이블뿐. **Airbnb 대비 명확한 약점.**

## SCR-H05 계약 관리 `/host/contract` ★

**상단 요약 타일**: 승인대기 · 입주예정 · 퇴실예정 · 퇴실점검

**필터**: `입주일 | 퇴실일` 토글 + 시작일~종료일 범위 + 검색(주소, 방 이름) + 정렬(최신순)

**상태 칩 (계약 상태 enum 완전 목록)**
```
전체 · 계약대기 · 입주대기 · 거주중 · 퇴실중 · 계약종료 · 취소 · 결제취소
```

**카드 구조**
```
[상태 배지]                              (거주중일 때) [입주•퇴실 일정] 링크
썸네일 | 방 이름
       | 주소
       | 임차인  {이름}
       | [채팅하기] [전화하기]      ← 전화하기는 특정 상태에서만 노출
───────────────────────────────────────
  하위 행 (계약 시도별):
  [결제완료] 2026.07.26(일) ~ 2026.08.29(토)  2,210,000원  [정산완료]  ›
  [취소] 임차인이 결제하지 않아 취소되었습니다.  …  ~~2,210,000원~~   ›
  [더보기]
```

**관찰된 취소 사유 문구 (= 취소 유형 enum)**
| 문구 | 의미 |
|---|---|
| `다른 임차인의 결제로 취소되었습니다.` | **동일 기간 복수 승인 → 선결제자 확정, 나머지 자동 취소** |
| `임차인이 결제하지 않아 취소되었습니다.` | 승인 후 결제 기한 초과 |
| `계약이 취소되었습니다.` | 일반 취소 |

> 💡 **핵심 비즈니스 규칙**: 임대인은 같은 기간에 대해 **복수의 계약 요청을 동시에 승인**할 수 있고, **먼저 결제한 임차인이 확정**된다. 나머지는 자동 취소. → 공실 리스크를 낮추는 대신 임차인 경험은 나빠지는 트레이드오프. (새 서비스에서 재검토할 지점)

## SCR-H06/07 정산 `/host/pay` ★

**목록** — 탭 `정산 예정 | 정산 완료`(`?status=complete`), 기간 필터(기본 6개월), 전체보기 필터, **[엑셀파일 내려받기]**
합계: `총 N건  N원`
컬럼: `정산(예정)일 | 방 이름 | 계약자 | 임대기간 | 총 정산 금액 | [상세보기]`

**상세** `/host/pay/{payId}`
```
계약 정보 : 방 이름 · 계약자 · 임대기간
정산 금액 :
   이용 금액              2,210,000원
     임대료                1,800,000원   (주간 임대료 × 주수)
     장기 계약 할인          -90,000원
     관리비                  500,000원   (주간 관리비 × 주수)
     청소비                        0원
   계약 수수료              -72,930원   ← 이용금액 × 3.3%
   ─────────────────────────────
   총 정산 금액            2,137,070원
입금 계좌 : {은행명} {계좌번호} ({예금주})
입금일    : 2026.07.26
```

### 💰 플랫폼 수익 모델 (역산 완료)

| 항목 | 요율 | 기준 |
|---|---|---|
| **임차인 계약 수수료** | **9.9%** | (임대료 + 관리비 + 청소비) |
| **임대인 계약 수수료** | **3.3%** | 이용금액 (할인 적용 후 임대료 + 관리비 + 청소비) |
| **합계 take rate** | **≈ 13.2%** | |

**검증** (정산 완료 7건 전부 일치)
| 이용금액 | 정산금액 | 배수 |
|---|---|---|
| 2,210,000 | 2,137,070 | ×0.967 ✓ |
| 1,765,400 | 1,707,142 | ×0.967 ✓ |
| 966,000 | 934,122 | ×0.967 ✓ |
| 1,716,000 | 1,659,372 | ×0.967 ✓ |
| 2,120,000 | 2,050,040 | ×0.967 ✓ |
| 940,000 | 908,980 | ×0.967 ✓ |
| 880,000 | 850,960 | ×0.967 ✓ |

### ⏱ 정산 시점 — 중요

| 정산일 | 임대기간 시작 | 차이 |
|---|---|---|
| 2026.07.26 | 2026.07.26 | D+0 |
| 2026.06.29 | 2026.06.28 | D+1 |
| 2026.06.17 | 2026.06.15 | D+2 |
| 2026.05.17 | 2026.05.17 | D+0 |
| 2026.04.01 | 2026.03.31 | D+1 |

> **정산은 입주일 기준 D+0~D+2에 실행** — 퇴실 후가 아님. 임대인은 입주 직후 임대료 전액을 수령.
> **보증금만** 퇴실 → 임대인 퇴실 점검 → 반환 경로를 따름.
> ⇒ 임대인 현금흐름이 매우 빠름. **33m2의 강점** (Airbnb는 체크인 24시간 후 지급).

## SCR-H05b 계약 상세 `/host/contract/{cid}`

```
단기임대계약   [결제완료] [연장]        ← 결제상태 배지 + 계약유형 배지
방 정보   : 방 이름 · 도로명(상세주소 포함) [복사] · 지번 [복사] · [방 세부 정보 ›]
임대인    : 이름 · 연락처
임차인    : 이름 · 연락처 · [채팅하기]
임대기간  : N주 · 입주일 · 퇴실일
정산금액  : (정산 상세와 동일 구조)
            * 연장계약에서는 청소비가 청구되지 않습니다.
            정산일 + [정산완료] 배지
```

> 🔐 **프라이버시 전환점**: 계약 확정 후 **양측 전화번호**와 **상세 주소(동/호수)** 가 공개됨.
> 계약 전에는 지번/도로명까지만, 상세주소·연락처 비공개.

> 🔗 **연장 계약**: `연장` 배지가 붙은 **별도 계약 레코드**로 생성. 청소비 면제.

## SCR-H05c 입주•퇴실 일정 `/host/contract/{cid}/schedule`

```
총 임대기간   9주   2026.06.28(일) ~ 2026.08.29(토)   ← 원계약+연장 합산

입주 및 퇴실 현황  (타임라인)
 ✓ 계약 확정      2026.06.26 11:04
 ● 거주중         2026.06.28 22:48
 ○ 퇴실
 ○ 임대인 확인
 ○ 보증금 반환
```

> 원계약(4주) + 연장(5주) = **9주로 합산 표시**. 연장 체인이 하나의 연속 임차로 렌더링됨.
> 각 단계에 **타임스탬프** 기록 → 계약 이벤트 로그 테이블 존재 추정.

## SCR-H08 채팅 `/host/chat`

- 헤더: "채팅" + **[자동 메시지 ›]**
- 좌측 목록: 전체보기 ▾ + 검색(주소, 방 이름)
  - 항목 = 아바타 · **계약 상태 배지**(거주중/이용완료/취소/계약종료) · 방 이름 · 날짜 · 계약기간 · 마지막 메시지 미리보기 · 상대 이름
- 우측 대화: 상대 이름 + 방 이름 링크 + 홈 아이콘 + 검색 아이콘
  - 말풍선 + 시간(오전/오후 H:MM), 날짜 구분선
  - 입력: 카메라(사진 첨부) + 텍스트 + [전송]

> 💬 **채팅 스레드 = 계약 단위**. 상태 배지가 스레드에 직접 붙음.

### 자동 메시지 `/host/chat/scheduled`, `/host/chat/scheduled/add`

| 필드 | 값 |
|---|---|
| 제목 | 최대 20자, **임차인에게 노출 안 됨** (내부 라벨) |
| 내용 | 1000자 |
| **전송 시점** | `계약 확정 즉시` / `입주일` / `퇴실일` |
| 오프셋 | `당일, 1일 전, 2일 전, 3일 전, 4일 전, 5일 전` |
| 시각 | `08:00 ~ 22:00` (1시간 단위) |
| **방 연결** | 발송 대상 매물 선택 (복수 매물 대응) |

> 계약 라이프사이클 이벤트에 앵커된 메시지 자동화. 입주 안내·퇴실 안내 표준화에 사용.

## SCR-H11 호스트 계정 `/host/my/account`

- 동일 계정에 역할 라벨만 **임대인**으로 표시 (게스트 모드에서는 **임차인**) → **단일 User, 이중 역할**
- 임대인 정보: 이메일 · 이름 · 비밀번호(+확인) · 휴대폰 · 프로필 사진(선택) · **임대인 소개(30자)**
- **정산 정보**
  | 항목 | 내용 |
  |---|---|
  | 정산 대금 입금 계좌 | `{은행} {계좌번호} ({예금주})` |
  | 수수료에 대한 영수증 발급 | 신청 / 미신청 + 전자세금계산서 사업자번호 |
- 안내(세무 구조):
  - 플랫폼은 **임대인이 지불한 수수료(3.3%)에 대한 영수증**만 발행
  - **임차인 이용금액(임대료·관리비·청소비)의 영수증은 임대인이 임차인에게 직접 발행** (플랫폼은 중개자)
  - 임차인 **입주 시점**의 영수증 정보 기준으로 발행, 미입력 시 자진발급 처리
- 회원탈퇴 `/host/my/account/delete`
