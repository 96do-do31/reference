# 33m2 ↔ Airbnb 비교 분석

새 서비스 방향성 결정을 위한 대조표. 각 항목은 역설계 문서의 관찰 근거에 기반합니다.
`✅ 검증` = 데이터로 확인 · `👁 관찰` = UI로 확인 · `❓ 추정` = 미검증

| | 33m2 | Airbnb |
|---|---|---|
| **본질** | 국내 **중장기 임대차 계약** 플랫폼 (중개 + 에스크로) | 글로벌 **단기 숙박 예약** 플랫폼 (중개 + 결제) |

| **핵심 약점** | 발견 경험 빈약, 가격 유연성 없음, 인원 개념 부재 | 중장기 임대차 고유 개념(보증금·정산·연장) 부재 |

## 1. 예약/계약 상태 머신 ★ 가장 큰 구조 차이

**33m2** ✅ 검증
```
계약 요청 → 임대인 승인(24h 내) → 결제 → 입주 → 퇴실 → 임대인 퇴실 확인 → 보증금 반환
```
상태 enum: `계약대기 · 입주대기 · 거주중 · 퇴실중 · 계약종료 · 취소 · 결제취소`

**Airbnb** 👁 관찰
```
(즉시예약)  예약 → [결제 or 후불 예약] → 체크인 → 체크아웃 → 상호 리뷰
(예약요청)  요청 → 호스트 승인 → 결제 → …
```

| 축 | 33m2 | Airbnb |
|---|---|---|
| 승인 필요 | **항상** | 선택 (즉시 예약 / 예약 요청) |
| 결제 시점 | **승인 후** | 예약 시 (또는 **수수료 없는 후불** — 체크인 D-9 자동청구) |
| 동시 승인 | **가능 — 선결제자 확정, 나머지 자동취소** ✅ | 불가 (예약 시 확정) |
| 종료 후 단계 | **퇴실 확인 → 보증금 반환** | 상호 리뷰 |
| 연장 | **별도 계약 레코드(`연장` 배지), 청소비 면제, 기간 합산 표시** ✅ | 예약 변경 요청 |

> 🔴 **33m2의 "선결제자 확정" 규칙은 임차인 경험상 명백한 결함**입니다. 승인받고 결제하려다 "다른 임차인의 결제로 취소되었습니다"를 보게 됩니다. 공실 리스크를 임차인에게 전가하는 구조.
> 🟢 반면 **퇴실 확인 → 보증금 반환** 단계는 임대차에 반드시 필요하며 Airbnb에 없습니다.

## 2. 요금 모델 ★ 설계 철학이 정반대

**33m2 — 항목 분해형** ✅ 검증 (`rid=100260`, 2주)
```
임대료      240,000   (주간요율 × 주수, 장기할인 적용)
관리비       60,000   (주간요율 × 주수)
청소비       30,000   (1회성, 연장계약은 면제)
계약 수수료   32,670   (= 위 합계 × 9.9%)
─────────────────
실 이용 금액 362,670
보증금      330,000   (플랫폼 고정, 반환 대상)
─────────────────
최종 결제   692,670
```

**Airbnb — 올인 단일가형** ✅ 검증
```
13박 x ₩37,846      492,000
주 단위 숙박 할인     -39,360
─────────────────
총액                452,640
```
「요금 상세 내역」을 펼쳐도 **동일한 2줄** — 청소비·서비스 수수료·세금 별도 항목 없음.

| 축 | 33m2 | Airbnb |
|---|---|---|
| 표시 | 4항목 분해 + 보증금 별도 | 총액 1개 (수수료 내재화) |
| 게스트 수수료 | **9.9%** (명시 노출) ✅ | 0 (요금에 포함) ✅ |
| 호스트 수수료 | **3.3%** ✅ | 미확인 ❓ (host-only 구조 추정 → 더 높을 가능성) |
| 플랫폼 take | **≈13.2%** ✅ | 미확인 ❓ |
| 보증금 | **330,000원 고정** (호스트 설정 불가) ✅ | 없음 (AirCover로 대체) |
| 다이나믹 프라이싱 | ❌ 없음 | ✅ 날짜별 요금 |
| 할인 | 장기계약(주수별 %), 즉시입주(일수별 만원) | 주간/월간 할인 |

> 🔀 **결정 지점**: 분해형은 투명하지만 총액 체감이 커지고 비교가 어렵습니다. 올인형은 단순하고 비교가 쉽지만 관리비·청소비가 실재하는 국내 임대차에서는 부적합할 수 있습니다.
> **절충안**: 검색·카드에는 **올인 총액**, 상세·결제에는 **분해 내역**. (Airbnb도 필터에 "모든 수수료 포함"을 명시하면서 상세는 제공)

## 5. 리뷰 & 신뢰 — Airbnb 우위, 단 33m2도 좋은 아이디어 보유

| 축 | 33m2 | Airbnb |
|---|---|---|
| 평점 | 단일 총점 (5점) | 총점 + **6개 카테고리** (청결도·정확도·체크인·의사소통·위치·가격대비만족도) |
| 분포 | 없음 | **히스토그램** (5→1) |
| 태그 리뷰 | ✅ **템플릿 기반** (`FAST_RESPONSE`, `KIND_HOST` …) + `isForHost`로 호스트/매물 평가 분리 | 카운트 붙은 태그 칩 (교통 편의성 9, 가격 대비 만족 8 …) |
| 리뷰어 정보 | 마스킹된 이름 + 연월 | 이름 + **가입 기간** 또는 거주지 + 상대 날짜 |
| 상호 리뷰 | ❓ (호스트→임차인 미확인) | ✅ 양방향 |
| 호스트 지표 | 우수임대인 · 본인인증 · 평점 · 후기수 · 임대 경력 | + **응답률 · 응답 시간** · 공동 호스트 |

> 🟢 33m2의 **`isForHost` 플래그로 호스트 평가와 매물 평가를 분리한 태그 스키마**는 Airbnb보다 깔끔합니다. 이건 가져갈 만합니다.
> 🔴 6개 카테고리 평점과 응답률/응답시간은 33m2에 없고, 중장기 임대에서 특히 중요합니다(오래 살수록 호스트 대응이 중요).

## 10. 아키텍처 / API 철학

| 축 | 33m2 | Airbnb |
|---|---|---|
| 프론트 | Next.js App Router (RSC 중심) | SSR + 하이드레이션 |
| API | REST `/v1/use-auth/…`, 엔벨로프 `{code, data}` | GraphQL `/api/v3/{Op}/{hash}` |
| 응답 성격 | **도메인 엔티티** (`usingFee`, `mgmtFee`) | **프레젠테이션 완제품** (`"13박 x ₩37,846"`, 접근성 문구까지) |
| 페이지 구성 | 고정 레이아웃 | **타입 지정 섹션 배열** (PDP 28섹션) |
| 필터 전달 | 개별 쿼리 파라미터 | **제네릭 `rawParams[{filterName, filterValues}]`** |
| 페이지네이션 | `page`/`size` | **커서** (base64 offset) |
| 인증 | Firebase Auth | 자체 |
| 지도 | 네이버(검색) + 카카오(상세) | Google |

> 💡 **우리 서비스 권장**: 도메인 엔티티 REST(33m2식)를 기본으로 하되, **금액 계산 결과는 서버가 확정해 내려주기**(33m2도 `discountedUsingFee`로 이미 그렇게 함). 섹션 배열 아키텍처는 초기에 과합니다. `rawParams` 제네릭 필터와 커서 페이지네이션은 채택할 만합니다.

## 12. 종합 — 가져올 것 / 버릴 것 / 새로 만들 것

### 🟢 33m2에서 가져올 것
1. **입주 시점 정산** (호스트 현금흐름 — 공급 확보의 핵심)
2. **보증금 에스크로 + 퇴실 확인 게이트** (임대차 필수)
3. **`missingOptions`** — 없는 옵션 명시로 분쟁 감소
4. **태그 리뷰 스키마** (`isForHost`로 호스트/매물 분리)
5. **계약 라이프사이클 자동 메시지**
6. **매물 복사하기** (다호실 운영)
7. **알림 설정 구조** (카카오톡 채널 + 방해금지 + 거래성 알림 예외)
8. **입주일/퇴실일 개별 턴오버 제어**
9. **양방향 대칭 위약금** (임대인 귀책 시 동일 기준 지급)

### 🟢 Airbnb에서 가져올 것
1. **수용 인원(게스트 수)** 1급 도입
2. **6개 카테고리 평점 + 평점 분포**
3. **호스트 응답률·응답 시간**
4. **풍부한 필터** (가격 히스토그램, 하위 지역, 편의시설, 접근성)
5. **실시간 결과 수 반영 CTA**
6. **대체 날짜 제안** ("비슷한 날짜에 예약 가능")
7. **날짜별 다이나믹 프라이싱**
8. **즉시 예약 옵션**
9. **수수료 없는 후불 결제**
10. **편의시설 의미 기반 분류** (특히 `안전`)

### 🔴 버릴 것 (두 서비스의 약점)
1. **33m2의 "선결제자 확정" 경쟁 승인** — 임차인에게 리스크 전가. 승인=선점(홀드) + 결제 기한으로 대체
2. **33m2의 목록/상세 `propertyType` 표기 불일치** (한글 vs enum) — enum 단일화
3. **33m2의 상세 새 탭 강제 열기** — 사용자 선택에 맡기기
4. **Airbnb의 요금 완전 불투명** — 관리비·청소비가 실재하는 국내 임대차에선 최소한 상세에서 분해 필요

### 🆕 새로 만들 것 (둘 다 없는 것)
1. **중장기 전용 검색 축** — 통근 시간, 학교/직장 기준 거리, 실입주 가능일
2. **12주 상한 없는 연속 계약** — 연장을 예외가 아닌 1급 개념으로
3. **관리비 실비 정산** (33m2는 "정산 대행하지 않음"이 명시적 한계)

> ⚠️ **정정**: 초판에서 "계약서 전자서명"을 둘 다 없는 것으로 분류했으나 **오류**였습니다.
> 33m2 FAQ 원문: *"종이 계약서를 별도로 작성하지 않더라도, 전자계약을 통해 임대인과 임차인의 계약 내용을 명확하게 기록하고 있으며, 해당 전자계약은 **종이 계약서와 동일한 법적 효력**을 가집니다."*
> ⇒ 33m2는 이미 전자계약 체계를 갖추고 있습니다. 새 서비스도 **필수**로 포함해야 합니다.
