# 웹 반응형 레이아웃 역설계 — 33m2 · Airbnb (Phase 4)

> **범위**: 웹(브라우저) 데스크톱↔모바일 레이아웃 전환. 네이티브 앱 IA·px 스펙은 `mobile-apps.md` 참조.
> **방법**: 서버 렌더링 페이로드를 **모바일 UA vs 데스크톱 UA**로 각각 수집해 컴포넌트 트리·Tailwind 클래스 실측.
> 원본: `_shared/captures/responsive/*.html` (mobile/desktop UA 쌍), 앱 px는 `_shared/captures/mobile/*.xml`.
> 33m2 `design-system.md`의 브레이크포인트 절과 짝을 이룸.

## 0. 한눈에 — 두 서비스의 반응형 전략이 정반대 ★

| 축 | 33m2 | Airbnb |
|---|---|---|
| **전략** | **서버 UA 적응형** (`isMobile`) | **클라이언트 CSS 반응형** |
| DOM 트리 | 모바일/데스크톱 **별도 컴포넌트 트리 SSR** | **단일 DOM** + 미디어쿼리 |
| 판정 시점 | 서버(요청 UA) | 브라우저(뷰포트 폭) |
| 페이로드 | 모바일 ~710KB / 데스크톱 ~967KB (guest/main) | 동일 HTML, CSS로 분기 |
| JS 번들 | **동일 29 청크** (트리만 다름) | 동일 |
| 데스크톱 폭 | **고정 1080px 중앙정렬** (유동 아님) | 유동 (max-width 컨테이너) |
| 브레이크포인트 | Tailwind 기본 640/768/1024/1280 | DLS **744 / 950 / 1128** |
| 모바일 네비 | **하단 고정 탭바**(앱 IA 복제) | 상단 축소 + 하단 CTA |

> **새 서비스 결정 포인트**: 33m2식 서버 UA 이중 트리는 SEO·초기 렌더는 좋으나 트리 2벌 유지비가 큼.
> 웹 우선·단일 코드베이스라면 **Airbnb식 단일 반응형 트리**가 유지보수에 유리. §8 권고 참조.

## 1. 33m2 — 서버 UA 적응형 렌더링 ✅ 실측

같은 URL을 UA만 바꿔 요청하면 **응답 크기·컴포넌트 트리가 달라짐**. 서버가 `isMobile`로 분기해
모바일 전용 트리 / 데스크톱 전용 트리를 각각 SSR한다.

```
GET https://web.33m2.co.kr/guest/main
  UA=iPhone   → 709,579 B  (모바일 트리)
  UA=Chrome/Mac → 966,588 B (데스크톱 트리)
동일 JS: /_next/static/chunks/*.js 29개 (양쪽 완전 일치)
```

- 클라이언트 미디어쿼리로 같은 마크업을 재배치하는 게 **아님** — 서버가 다른 마크업을 내려줌.
- 결과: 모바일 브라우저에서 데스크톱 폭으로 늘려도 데스크톱 레이아웃이 안 나오고, 그 반대도 마찬가지(뷰포트 리사이즈로 관찰 실패했던 이유 = 이 구조 때문).
- 재현: `curl -A "<mobile UA>"` vs `curl -A "<desktop UA>"`.

### 1.1 브레이크포인트 (Tailwind v4 기본)

| 토큰 | 값 | 33m2 용도(실측) |
|---|---|---|
| `sm` | 640px | 국소 |
| `md` | **768px** | **모바일 트리 내부의 주 분기** — 카테고리 그리드 3→6열, 여백/간격 확대 |
| `lg` | 1024px | 데스크톱 2단 전환(추정) |
| `xl` | 1280px | 국소 |

> 모바일 트리조차 mobile-first로 짜여 `md:` 프리픽스(768px)로 태블릿+ 대응(관찰된 `md:` 26종:
> `md:grid-cols-6` `md:grid-cols-2` `md:gap-10` `md:pt-10` `md:flex-col` `md:size-10` 등).

### 1.2 데스크톱 레이아웃 골격

- **고정 1080px 중앙정렬**: `w-[1080px] mx-auto` 16회. 뷰포트가 넓어도 콘텐츠 폭은 1080px 고정, 좌우 여백만 증가.
- 상단 GNB(글로벌 네비게이션 바) + 히어로/검색 → 카테고리 그리드 → 매물 캐러셀.
- 카드 히어로 오버레이: `h-[170px] w-full` + `backdrop-blur-lg` (하단 그라데이션 정보 패널).
- 하단 고정 바 **없음** (네비는 상단 GNB로 해결).

### 1.3 모바일 웹 레이아웃 골격

- 유동 폭, 콘텐츠 `max-w-[335px]` 중앙정렬 계열, 좌우 여백 15dp(45px@3x — 앱과 동일, `mobile-apps.md`).
- 카테고리 그리드 `grid-cols-3` → `md:grid-cols-6`.
- 카드 히어로 오버레이: `h-[113px] w-[189px]` (데스크톱보다 작고 고정폭).
- 상단은 압축 헤더(로고+검색 진입), **하단은 전역 고정 탭바**(§1.4).
- 상단에 **앱 다운로드 배너**(“다운로드” 문구) — 데스크톱에는 약하거나 없음.

### 1.4 모바일 웹 하단 고정 탭바 ★ (앱 IA를 웹이 복제)

**모든** 모바일 페이지(홈·검색·매물상세·호스트)에 동일하게 존재:

```
class: fixed right-0 bottom-0 left-0 z-50 bg-white
       after:absolute after:top-0 after:left-0 after:h-[0.5px] after:w-full after:bg-gray-200
= 화면 하단 전폭 고정 · 흰 배경 · 상단 0.5px 헤어라인 구분선 · z-50
```

- 탭(게스트/비로그인): **홈 · 지도 · 계약 · 채팅 · 마이** — 네이티브 앱 5탭 IA와 동일(`mobile-apps.md` §1).
- 데스크톱에는 이 바가 **전혀 없음**(0종). → 모바일 웹은 사실상 **앱 셸을 웹으로 재현**.
- 홈에는 지도 진입 플로팅 버튼도 존재(하단바 인근 “지도”).

### 1.5 데스크톱↔모바일 화면별 차이 (요약)

| 화면 | 데스크톱 | 모바일 웹 |
|---|---|---|
| 전역 네비 | 상단 GNB | **하단 고정 탭바(5)** + 압축 상단 |
| 홈 | 1080px 고정, 카테고리 6열급 | 유동, 카테고리 3열(→md 6열) |
| 검색/목록 | 데스크톱 트리(좌 목록+우 지도 추정) | 모바일 트리, 지도 탭 전환 |
| 매물 상세 | 본문 + (예약/문의 카드) | 본문 스크롤 + 하단 탭바 상시 |
| 카드 오버레이 | 170px 전폭+블러 | 113×189px 고정 |

> 검색 결과의 “좌 목록 / 우 지도” 데스크톱 2단은 `lg`(1024) 전환으로 추정(🟡). 모바일은 목록↔지도 **탭 전환**(앱 §2.7과 동일 패턴).

## 2. Airbnb — 클라이언트 CSS 반응형 ✅ 실측(디자인토큰)

단일 DOM을 브라우저가 뷰포트 폭으로 재배치. 33m2와 달리 서버가 UA로 트리를 바꾸지 않음.

### 2.1 브레이크포인트 (DLS)

| 토큰 | 값 | 미디어쿼리 사용 빈도 |
|---|---|---|
| **sm** | **744px** | 22 (최다) — 모바일↔태블릿 경계 |
| **md** | **950px** | 9 |
| **lg** | **1128px** | 12 — 데스크톱 최대 그리드 |

> 744 미만 = 모바일(1열 카드 + 하단 스티키 예약바), 744~1128 = 태블릿(2열), 1128+ = 데스크톱(그리드 최대).
> 그 외 100여 미디어쿼리는 컴포넌트 국소 대응(`design-system.md` §브레이크포인트).

### 2.2 데스크톱↔모바일 주요 차이 (관찰)

| 화면 | 데스크톱 | 모바일 웹 |
|---|---|---|
| 검색 | 상단 검색바(펼침) + 좌 카드그리드/우 지도 | 상단 축소 검색 pill, 지도 전체화면 토글 |
| PDP | 갤러리 그리드(5분할) + 우측 **스티키 예약카드** | 세로 갤러리 + **하단 스티키 예약바**(가격+예약 버튼) |
| 체크아웃 | 2단(좌 폼/우 요약) | 1단, 요약 접힘 |
| 네비 | 상단 GNB(로고/메뉴/프로필) | 상단 축소 + 하단 탭(앱), 웹은 상단 위주 |

> Airbnb PDP의 **우측 스티키 예약카드 → 모바일 하단 스티키 예약바** 전환은 표준 패턴.
> 새 서비스 매물 상세에 그대로 차용 가치 있음(§8).

## 3. 네이티브 앱 (px 실측) — 교차 참조

웹 반응형과 별개로, **네이티브 앱**은 uiautomator XML로 px 단위 실측 완료(0%→88%).
좌표·거터·비율 스펙은 `mobile-apps.md` + `_shared/captures/mobile/*.xml`(20+ 화면). 예:

- 페이지 좌우 여백 45px(15dp), 히어로 1080×788(1.37:1), 홈 카드 2열 폭 478px·거터 34px(11dp).

> 웹 모바일과 앱은 **동일 IA(하단 5탭)**를 공유 → 하나의 모바일 UX 명세로 통합 가능.

## 4. 재현/검증 방법

```bash
# 33m2 서버 UA 적응형 — 트리가 UA로 갈림
curl -sL -A "<iPhone UA>"  https://web.33m2.co.kr/guest/main -o m.html   # 모바일 트리
curl -sL -A "<Chrome UA>"  https://web.33m2.co.kr/guest/main -o d.html   # 데스크톱 트리
# 하단 탭바 존재 여부로 트리 판별:  grep 'fixed right-0 bottom-0 left-0 z-50' → 모바일만 매치
# 데스크톱 고정폭 확인:            grep 'w-\[1080px\] mx-auto'                → 데스크톱만 다수
```

## 6. 새 서비스 반응형 권고 (제안 — 확정 아님)

1. **단일 반응형 트리 채택**(Airbnb식). 33m2식 서버 UA 이중 트리는 트리 2벌 유지비·불일치 위험. 웹 우선·단일 코드베이스에 부적합.
2. **모바일 하단 탭바는 유지**(33m2 강점). 웹 모바일에서도 앱과 동일한 하단 5탭 → 웹/앱 UX 연속성. 데스크톱에서는 상단 GNB로 전환.
3. **매물 상세 예약/문의 카드**: 데스크톱 우측 스티키 → 모바일 하단 스티키 바(Airbnb 패턴).
4. **브레이크포인트**: 33m2 톤을 따르되 3대 분기(모바일<768 / 태블릿 768~1024 / 데스크톱 1024+)로 단순화. 데스크톱은 고정폭 대신 max-width 컨테이너(예: 1080~1200) 권장.
5. **검색 목록↔지도**: 모바일 탭 전환, 데스크톱 좌우 2단 — 두 서비스 공통 패턴.
